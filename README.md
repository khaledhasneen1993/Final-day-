# Final Day — إشارات Telegram

يراقب عقود Binance USDT-M الدائمة عبر بيانات السوق العامة ويرسل إشارات Long وShort إلى محادثة Telegram واحدة. يتطلب Python 3.11 أو أحدث.

## إعداد وتشغيل

1. أنشئ بوتًا عبر `@BotFather`، ثم افتح محادثته واضغط **Start**.
2. جهّز توكن البوت ومعرّف المحادثة. للمحادثة الخاصة، أرسل رسالة إلى البوت ثم استخدم طريقة [getUpdates](https://core.telegram.org/bots/api#getupdates) واقرأ `message.chat.id`. إذا ظهر Webhook نشط، راجع إعدادات البوت قبل تغيير طريقة استقبال التحديثات.
3. من مجلد المستودع، جهّز البيئة وثبّت الاعتماديات:

   ```bash
   python -m venv .venv
   source .venv/bin/activate
   python -m pip install -r requirements.txt
   ```

4. أنشئ ملفًا محليًا اسمه `.env.telegram` وضع فيه:

   ```bash
   TELEGRAM_BOT_TOKEN='ضع التوكن هنا'
   TELEGRAM_CHAT_ID='ضع معرّف المحادثة هنا'
   ```

5. حمّل الإعدادات وشغّل البوت:

   ```bash
   set -a
   source .env.telegram
   set +a
   python -u run_telegram.py
   ```

## شروط الإشارة

- يراقب حتى **50 عقدًا** مرتبةً حسب حجم تداول 24 ساعة، بحد أدنى **15 مليون USDT**. يحدّث القائمة كل **10 دقائق** ويتابع الشموع باستمرار عبر WebSocket. إذا تعذّر جلب قائمة السوق، يستخدم BTC وETH وSOL مؤقتًا.
- يشترط حركة سعرية تتجاوز **1%** صعودًا للـ Long أو هبوطًا للـ Short مقارنة بإغلاق الشمعة قبل دقيقتين، وحجمًا أكبر من **3.5×** متوسط 12 شمعة سابقة.
- يؤكد الاتجاه باختلال دفتر الأوامر لأول 20 مستوى، فوق **+0.35** للـ Long وتحت **−0.35** للـ Short.
- يرسل العملة والاتجاه وسعر تحقق الشروط والستوب والهدف. الهدف يبعد **1%** باتجاه الصفقة.
- يستخدم آخر قاع مؤكد تحت السعر للـ Long أو آخر قمة مؤكدة فوقه للـ Short، مع شمعتين مغلقتين على كل جانب. عند غياب نقطة مؤكدة، يستخدم أدنى قاع صالح أو أعلى قمة صالحة من الشموع المغلقة المتاحة. يتجاوز الإشارة عند غياب مستوى صالح.
- يجدول تنبيهًا واحدًا لكل عملة واتجاه في شمعة الدقيقة خلال تشغيل العملية.

## لوحة Termux

يفتح الأمر نفسه لوحة على [http://127.0.0.1:8765](http://127.0.0.1:8765) من متصفح الهاتف، ما دامت عملية البوت تعمل. استعمل `--port` إذا كان المنفذ مستخدمًا. تتحدث قائمة العقود والصفقات تلقائيًا كل ثانيتين.

عند تأكيد Telegram استلام الرسالة، تسجل اللوحة صفقة متابعة افتراضية بسعر الإشارة وهدفها وستوبها. تفحص أسعار الصفقات المفتوحة كل خمس ثوانٍ تقريبًا، بما فيها العقود التي خرجت من قائمة المسح، وتسجل الإغلاق عند رصد تجاوز الهدف أو الستوب. قد يفوت الفحص حركة حدثت بين رصدين أو أثناء إيقاف البوت. تعرض اللوحة حركة السعر باتجاه الصفقة دون رسوم أو هامش. يستخدم البوت بيانات Binance العامة فقط ولا يرسل أوامر تداول.

يُحفظ السجل في `final-day.sqlite3` داخل مجلد التشغيل، ويُستعاد عند إعادة تشغيل البوت من المجلد نفسه. يمكن تحديد مسار آخر باستخدام `--database`. تعمل اللوحة على الجهاز نفسه عبر عنوان loopback.

## Binance USD-M Demo عبر RSA

هذا المسار متاح على فرع `demo-rsa`. يستخدم أسواق Demo فقط، ولا يحتاج Telegram. محرك الإشارة نفسه يقرأ بيانات Demo ويستهدف 1% من سعر الإشارة ويحسب وقف Demo عند تحرك السعر 3% بعكس الاتجاه من متوسط سعر التنفيذ الفعلي، مع التقريب إلى أقرب درجة سعرية باتجاه الدخول. توضع أوامر الخروج الشرطية لدى Binance بعد تأكيد الدخول، بحجم لا يزيد عن المركز المرصود وبخاصية `reduceOnly`. يطلب قبل الدخول أعلى رافعة متاحة بحسب شرائح Binance لحجم الأمر في العقد، ويتحقق من تأكيدها. يبقى نوع الهامش حسب إعداد الحساب.

استخدم حساب Demo مخصصًا للبوت في وضع **One-way**، وشغّل عملية واحدة فقط لكل حساب وقاعدة بيانات. احفظ المفتاح الخاص بصيغة RSA PEM PKCS#8 محليًا، وأضف مفتاحه العام إلى Binance Demo لتحصل على API key. حمّل المتغيرين من ملف محلي خاص:

```bash
export BINANCE_DEMO_API_KEY='ضع مفتاح API التجريبي محليًا'
export BINANCE_DEMO_RSA_KEY_FILE='/path/to/private-key.pem'
```

من Termux داخل Debian، بعد تفعيل بيئة Python وتثبيت `requirements.txt`:

```bash
python run_demo.py --check
```

الفحص للقراءة فقط. بعد نجاحه، شغّل التداول التجريبي يدويًا وحدد قيمة المركز المستهدفة قبل الرسوم:

```bash
python -u run_demo.py --trade-demo --notional 20 --max-positions 1
```

القيمة 20 مثال قابل للتغيير، والأوامر تخضع لحدود الكمية والقيمة الدنيا لكل سوق. إذا انقطعت البيانات، يعيد الماسح الاتصال ويتجاوز الإشارات القديمة. عند مهلة REST أو نتيجة أمر غير مؤكدة، يستعلم برقم العميل المحفوظ ويواصل المصالحة من `final-day-demo.sqlite3` بعد إعادة التشغيل. قد تبقى خانة المركز محجوزة إذا لم تؤكد المنصة نتيجة أمر معلّق. لا يوجد Kill Switch أو أمر إغلاق طارئ بسبب التأخير. بعد قبول المنصة للستوب والهدف يظلان لديها أثناء انقطاع البوت. إذا رفضت أحدهما، يسجّل البوت حالة الحماية غير المؤكدة ويعيد فحصها، وقد يبقى المركز بلا تلك الحماية حتى قبولها. إذا أغلقت مركزًا من واجهة Binance، يرصد البوت أن المركز صار صفراً، ويصنّف التنفيذ الخارجي أو اليدوي إذا وجد تنفيذ خروج لا يطابق أوامره، ويلغي فقط أوامر الحماية التابعة لذلك المركز ثم يتيح دخولًا جديدًا. مراكز الإصدار السابق التي سُجّل لها وقف تحتفظ بسعر وقفها. لا تحذف قاعدة البيانات أثناء وجود مراكز أو أوامر يديرها البوت.

إذا توقفت العملية بعد إرسال الدخول، استأنف متابعة سجلها دون فتح مراكز جديدة بواسطة `python -u run_demo.py --recover`. استخدم نفس مجلد التشغيل وقاعدة البيانات التي استخدمتها عند إرسال الدخول. يستعلم البوت عن الأمر المحفوظ وعمليات تنفيذه ويستكمل أوامر الحماية. تحقق من أوامر الحماية في Binance Demo قبل استئناف التداول.
